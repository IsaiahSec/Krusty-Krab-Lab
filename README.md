# Krusty Krab Lab

A self-contained, simulated Active Directory enterprise network built for hands-on cybersecurity practice. Disposable, reproducible, and designed to be attacked, defended, broken, and rebuilt.

This repository accompanies the capstone project ***From Vulnerable to Hardened: Building, Attacking, \& Defending a Simulated LAN Environment Through Red Team and Blue Team Operations***, submitted in fulfillment of CSEC 4490 (Cybersecurity Capstone) at the University of Central Arkansas.

The repository deliberately omits configuration files that are either fully generated by an installer (OpenVPN `server.conf`, OpenVPN client `.conf` files) or are short, well-known templates that the report walks through editing inline (WordPress's `wp-config.php`). The configuration files hosted here are the ones authored from scratch or substantially extended by us — the Apache virtual host enabling HTTPS for the intranet, the Sysmon event filter configuration, and the custom Wazuh detection rules and active-response configuration.

## What the lab is

Six virtual machines hosted in VirtualBox on team members' personal hardware, networked together by an OpenVPN server running on a small AWS EC2 instance. The setup forms a small Active Directory domain (`krustykrab.local`) named after the team and the SpongeBob-themed user accounts populating it:

|Machine|OS|Role|
|-|-|-|
|`blueTeamADVM`|Windows Server 2016|Domain controller, DNS, MailEnable mail server, IIS|
|`blueTeamIntraVM`|Ubuntu 24.04 LTS|Intranet web server (WordPress, LDAP-integrated)|
|`blueTeamWin7VM`|Windows 7 Professional|Legacy domain-joined client|
|`blueTeamWin10VM`|Windows 10|Modern domain-joined client|
|`blueTeamSOCVM`|Kali Linux 2025.4|SOC workstation, Wazuh Manager, OpenVAS|
|`redTeamXUVM`|Xubuntu 24.04.3 LTS|Attacker workstation, off-domain|

Two snapshot sets are documented in the report — a **base** snapshot (functional but unhardened) and a **secure** snapshot (with GPO-deployed Wazuh, Sysmon, and active response, plus firewall hardening). The same attack scenarios are run against both snapshots to demonstrate the impact of detection and response on otherwise-vulnerable infrastructure.

## Replicating the lab

The capstone report ([`docs/report.pdf`](docs/report.pdf)) is the authoritative build guide. Read Section #2 end-to-end before attempting replication; the procedures are detailed and order-dependent. The figure gallery the report links to throughout is not duplicated in this repository (its size exceeds GitHub's per-file limit) — it's hosted publicly on Google Slides and is reachable via any figure link in the report itself.

This repository hosts the scripts and configuration files referenced in the report. Binaries, ISOs, and third-party installers are not redistributed here — they are linked below.

### Required downloads (not in this repository)

* **OpenVPN Server installer** — [Angristan's OpenVPN install script](https://github.com/angristan/openvpn-install) (commit pinned in report Section 2.2)
* **Wazuh agent (Windows)** — [wazuh.com/install](https://documentation.wazuh.com/current/installation-guide/wazuh-agent/wazuh-agent-package-windows.html)
* **Sysmon (current, for Windows 10 / Server 2016)** — [learn.microsoft.com/en-us/sysinternals/downloads/sysmon](https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon)
* **Sysmon v13.x (for Windows 7)** — Microsoft does not publish older Sysmon versions. Use an archived snapshot of the pre-2022 documentation page on the Wayback Machine: [web.archive.org/web/20210410215018/https://docs.microsoft.com/en-us/sysinternals/downloads/sysmon](https://web.archive.org/web/20210410215018/https://docs.microsoft.com/en-us/sysinternals/downloads/sysmon). Sysmon v14+ dropped Windows 7 support, so the v13.x build from this snapshot is required for `blueTeamWin7VM`.
* **OpenVPN client (Windows 7 / 8 / 10 / Server)** — [build.openvpn.net/downloads/releases/](https://build.openvpn.net/downloads/releases/) (versions documented in report Section 2.4.x for each machine)
* **VirtualBox** — [virtualbox.org](https://www.virtualbox.org/)
* **MailEnable Standard Edition** — [mailenable.com](https://www.mailenable.com/download.asp)
* **WordPress** — fetched in-place during intranet build via `wget` (Section 2.5.2.1.1)
* **Operating system ISOs** — links and notes in the relevant Section 2.4.x subsection per machine

### Lab credentials

The user passwords used throughout the scripts (`KrustyAdmin!`, `KrustyFryCook!`, `KrustyAcorns!`, `KrustyAnchor!`, `KrustyKlarinet!`, `KrustyPants!`) are documented in the report's Section 2.5.1.3.3 user table. These exist only within a disposable lab AD instance and have no meaning outside the simulated environment. If you replicate the lab, you may keep them as-is so the scripts run unmodified, or substitute your own and update the scripts accordingly.

For the 'phishing\_simulation...' scripts, you will need to provide your own Anthropic API key — the script reads it from the `ANTHROPIC\_API\_KEY` environment variable on each machine where it runs. See the comments at the top of the script.

## Disclaimer

The Krusty Krab Lab is built strictly for educational use within a fully isolated, disposable environment. Some scripts in this repository intentionally simulate adversarial behavior — including credential harvesting, e-mail spoofing, lateral movement, and process injection — for the purpose of red team / blue team exercises. **Do not deploy these scripts in any environment where they may affect real users, real data, or real infrastructure.** The authors assume no responsibility for misuse.
